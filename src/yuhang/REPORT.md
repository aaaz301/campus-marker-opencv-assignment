# 校内赛标志物识别报告

## 1. 任务目标

使用 C++ 和 OpenCV 传统视觉方法识别连续画面中的校内赛标志物，输出目标区域、四个角点和当前帧检测状态。

测试输入为 `data/raw/marker_video.avi`。实际读取的图像尺寸为 1440×1080。

本实现将发光图案的四个外角作为目标顶点，不将黑色安装板的四角作为输出。

## 2. 外观观察与设计思路

测试视频中的图案包含三个较完整的 L 形亮区，以及右上方的小 L 形亮区和小亮块。

根据该外观，本实现未直接采用示例中的细长灯条两两配对方法，而是使用亮度分割提取亮区，再结合轮廓形状、尺寸和相对位置判断目标。

开发中先显示灰度图、二值图、轮廓和局部外接框，观察参数效果。最终结果画面只保留目标四边形、角点标签和检测状态。

## 3. 方法流程

### 3.1 去噪和灰度转换

使用 3×3 中值滤波减少孤立噪点，然后将 BGR 图像转换为灰度图。

较小的滤波邻域用于减少噪点，同时尽量保留亮区边界和小亮块。

### 3.2 亮度阈值分割

将灰度值大于 200 的像素设为 255，其余设为 0。

该阈值在观察的测试片段中保留了主要发光区域，并排除了大部分背景。但亮度分割不能独立区分标志物和反光，因此需要后续几何检查。

### 3.3 轮廓与大 L 形候选

使用 RETR_EXTERNAL 提取外轮廓，使用 CHAIN_APPROX_SIMPLE 简化边界点。

对每条轮廓计算：

- 轮廓面积；
- 水平外接矩形；
- 填充比例：轮廓面积除以外接矩形面积；
- 宽高比：外接矩形宽度除以高度。

候选条件为：

- 填充比例大于 0.35、小于 0.60；
- 宽高比大于 0.7、小于 1.3。

在观察的片段中，三个较完整 L 形的填充比例约为 0.42～0.45，右上较小折角约为 0.72～0.76，小亮块约为 0.80～0.87。因此先将三个完整 L 形作为主要布局候选。

这些数值来自部分视频片段的观察，不代表所有尺度和姿态下的固定分布。

### 3.4 布局和尺寸检查

当前帧恰好有三个候选时，选择中心 y 坐标最小的候选作为上方候选。其余两个按 x 坐标区分左右。

检查：

- 两个下方中心均低于上方中心；
- 下方两点高度差小于其水平间距的 20%；
- 上方点与左下点的水平偏移小于下方水平间距的 20%；
- 三个候选外接矩形的最大面积与最小面积之比小于 1.5。

比例容差用于适应目标在图像中的大小变化。上述布局仍依赖接近正立的目标姿态，不具有完整的旋转和透视不变性。

### 3.5 右上区域搜索

以“上方中心 + 右下中心 - 左下中心”作为右上搜索参考位置。

搜索半径为下方中心水平间距的 40%。若某亮区外接矩形的中心位于该范围内，收集该亮区的全部轮廓点。

使用多个亮区的点，是因为右上图案由分开的亮块组成。预测位置仅用于搜索，不直接作为实际角点输出。

当前检查只要求搜索范围内存在轮廓点，尚未严格验证右上各亮块的具体排列。

### 3.6 四角点提取

从对应轮廓中选择方向极值：

- 左上：上方 L 形轮廓中 x+y 最小的点；
- 右上：右上搜索点集中 x-y 最大的点；
- 右下：右下 L 形轮廓中 x+y 最大的点；
- 左下：左下 L 形轮廓中 y-x 最大的点。

按 LT、RT、RB、LB 顺序保存四点，并连接成闭合四边形。

这些点是二值轮廓上的近似外角，可能受圆角、阈值、滤波和模糊影响，未进行亚像素优化。极值选点主要适用于当前接近正立的姿态。

## 4. 参数汇总

| 参数 | 当前值 | 用途 |
|---|---:|---|
| 中值滤波邻域 | 3×3 | 减少孤立噪点 |
| 灰度阈值 | 200 | 提取高亮区域 |
| 填充比例 | 0.35～0.60，严格不等式 | 筛选大 L 候选 |
| 宽高比 | 0.7～1.3，严格不等式 | 排除过细长的区域 |
| 下方高度差容差 | 水平间距的 20% | 检查下方对齐 |
| 左侧水平偏移容差 | 水平间距的 20% | 检查左侧对齐 |
| 最大与最小矩形面积比 | 小于 1.5 | 检查尺寸相近 |
| 右上搜索半径 | 水平间距的 40% | 收集右上亮区 |

这些参数通过当前测试视频中的观察进行初步选择，尚未进行系统参数搜索或跨场景验证。

## 5. 坐标、显示与视频输出

处理过程中未缩放或裁剪检测图像。输出坐标位于原始帧坐标系：

- 原点：图像左上角；
- x 方向：向右；
- y 方向：向下；
- 单位：像素。

结果显示绿色四边形、红色角点、顺序标签和检测状态。

每帧重新初始化检测状态，未通过当前帧检查时不绘制旧目标结果。当前未加入跨帧平滑或跟踪。

使用 VideoWriter 将标注结果写入 MJPG AVI。输出帧率读取自输入视频；无效时使用 30 FPS 备用值。处理结束后释放写入对象，完成文件保存。

## 6. 验证情况

开发环境：

- Ubuntu 22.04.5 LTS（WSL）；
- G++ 11.4.0；
- CMake 3.22.1；
- OpenCV 4.5.4；
- C++17。

已在原构建目录成功编译、运行，又在新的 build/yuhang-check 目录重新配置和编译，成功处理全部 1676 帧。

缺少输入参数时，程序输出“请提供一个视频路径”。代码还包含视频打开失败和零帧检查；尚未对所有错误分支进行专门测试。

人工观看仓库测试视频及输出结果，目标完整、清晰可见时，未观察到明显框闪烁、四边形交叉、角点跳错或明显背景误检。目标完全离开后显示未检测到，无残留目标框。

该验证没有逐帧标注真值，未计算准确率、召回率或角点误差。未进行另一套干净 Linux 环境复现和现场摄像头测试。

提交结果为 evidence/demo.mp4，时长 23.805 秒，大小约 6.3 MB，由标注 AVI 压缩为 H.264 MP4。

## 7. 失败情况和已知限制

调试中观察到，标志物位于画面边缘、亮区被截断时，部分区域的宽高比和填充比例发生变化，不再通过候选筛选。当前允许这类不完整目标返回未检测到。

其他已知限制：

- 额外候选或候选缺失会使“恰好三个”的条件失败；
- 光照、曝光和反光变化可能影响固定阈值；
- 明显旋转和透视变化可能破坏布局条件；
- 右上附近的干扰轮廓可能影响角点选择；
- 轮廓变化可能造成方向极值点跳动；
- 当前仅提供视频文件输入参数。

## 8. 改进思路

- 从多个候选中搜索合理组合，而不是要求候选数量恰好为三个；
- 增加 L 形方向和右上亮块排列验证；
- 比较其他亮度分割方法，提高光照适应性；
- 通过边线拟合及交点计算改进角点定位；
- 使用整体几何关系支持更大姿态变化；
- 在更多测试后加入有限的跨帧稳定处理，并确保目标消失时及时清除结果；
- 补充摄像头输入和现场连续帧测试。
